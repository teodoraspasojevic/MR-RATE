# Layer map: NVIDIA NV-Generate-MR-Brain UNet vs. the report-conditioned UNet

Generated by `scratchpad/dump_layer_map.py`. Both models are built from NVIDIA's own
`NV-Generate-CTMR/configs/config_network_rflow.json` (`diffusion_unet_def`), with
`use_flash_attention=False` so they build on CPU. That flag changes the attention *kernel*, never a
parameter or a module.

Base class: `monai.apps.generation.maisi.networks.diffusion_model_unet_maisi.DiffusionModelUNetMaisi`
(monai 1.6.0). The conditioned class subclasses it:
`mrrate_r2v.models.report_conditioned_unet.ReportConditionedUNetMaisi`.

## How to read this

Section 4 is **one** tree, not two. It is the conditioned model, and every line that the original
model does **not** have is prefixed with `+`. Delete every `+` line and you are left with the
original NVIDIA model, module for module, name for name. Nothing else was moved, renamed, resized or
removed -- that is the property the whole design depends on, and section 5 states the check.

`<-- N^3 feature map` marks the spatial size of the tensor entering that block, assuming a 256x256x256
volume (the autoencoder compresses 4x, giving a 64^3 latent). The model itself is resolution-agnostic.

One thing that can mislead: in section 4 the new modules all appear **at the bottom**, not next to the
blocks they act on. That is PyTorch listing modules in *registration* order, and the adapters are
created after `super().__init__()` has already registered the whole base UNet. Where they actually
*run* is section 2. Section 6 explains every monai-specific layer type that appears.

## 2. Where the new layers sit

Five cross-attention adapters, each applied to the tensor *entering* a block, plus one shared text
projection. Nothing is inserted *inside* any pretrained block.

```
x (4 latent channels)
  |
  conv_in
  |
  down_blocks.0                                             64^3, 64 ch
  down_blocks.1                                             32^3, 128 ch
+ down_cross_attn.2  ->  down_blocks.2                       16^3, 128 ch in
+ down_cross_attn.3  ->  down_blocks.3                        8^3, 256 ch in
+ mid_cross_attn     ->  middle_block                         8^3, 512 ch
+ up_cross_attn.0    ->  up_blocks.0                          8^3, 512 ch in
+ up_cross_attn.1    ->  up_blocks.1                         16^3, 512 ch in
  up_blocks.2                                               32^3, 256 ch in
  up_blocks.3                                               64^3, 128 ch in
  |
  out  ->  predicted noise/velocity (4 channels)

report embedding (B, L, 768)
  |
+ context_proj (768 -> 2048 -> 512)  ---> shared by all five adapters as K/V
+ null_context  (1, 1, 512)          ---> the learned "no report" token
```

The two levels chosen are exactly the two the pretrained model already has self-attention at
(`attention_levels: [false, false, true, true]`), plus the bottleneck. Conditioning at the block
*input* rather than its output is deliberate: the skip connection that leaves a down block is taken
after the adapter has run, so the decoder's skips carry the report too.

| adapter | acts on | channels in/out | heads x head_dim | feature map | params |
|---|---|---|---|---|---|
| `down_cross_attn.2` | input of down_blocks.2 | 128 / 128 | 4 x 32 | 16^3 | 197,504 |
| `down_cross_attn.3` | input of down_blocks.3 | 256 / 256 | 8 x 32 | 8^3 | 526,080 |
| `mid_cross_attn` | input of middle_block | 512 / 512 | 16 x 32 | 8^3 | 1,576,448 |
| `up_cross_attn.0` | input of up_blocks.0 | 512 / 512 | 16 x 32 | 8^3 | 1,576,448 |
| `up_cross_attn.1` | input of up_blocks.1 | 512 / 512 | 16 x 32 | 16^3 | 1,576,448 |

`context_proj` adds 2,626,560 and `null_context`
512, for 8,080,000 total.

## 3. One adapter in full

Every one of the five is this, with only the channel count changing. `C` is the block's channel
count, `L` the number of report tokens.

```
                                   x  (B, C, D, H, W)                    report context (B, L, 512)
                                   |                                          |
        +--------------------------+                                          |
        |                          |                                          |
    residual                    norm         GroupNorm(32, C)                  |
        |                          |                                          |
        |                       proj_in      Convolution 1x1x1, C -> C         |
        |                          |                                          |
        |                    flatten to (B, D*H*W, C)                          |
        |                          |                                          |
        |                      norm_attn     LayerNorm(C)                      |
        |                          |                                          |
        |                        attn        MaskedCrossAttention  <-----------+
        |                          |           to_q: C -> C  (from the image)
        |                          |           to_k: 512 -> C (from the report)
        |                          |           to_v: 512 -> C (from the report)
        |                          |           out_proj: C -> C
        |                          |
        |                  reshape back to (B, C, D, H, W)
        |                          |
        |                      proj_out      Convolution 1x1x1, C -> C   ** ZERO-INITIALISED **
        |                          |
        +-----------> ( + ) <------+
                        |
                     output
```

`proj_out` starts as all zeros (weight *and* bias), so the whole branch outputs exactly `0` and the
adapter is `x + 0 = x`. That is why the conditioned model reproduces the pretrained model bit for
bit before training. `norm` and `norm_attn` cannot disturb the original path either, because they act
on a *copy*: `residual` is the untouched input.

## 6. What the monai-specific layer types are

Most of the tree is plain PyTorch (`Conv3d`, `Linear`, `GroupNorm`, `SiLU`). These are the ones that
are monai's, and two of them matter for understanding the design. Line numbers are monai 1.6.0.

### Wrappers that look like layers but are not

| Class | Source | What it actually is |
|---|---|---|
| `Convolution` | `monai/networks/blocks/convolutions.py` | monai's conv + optional norm/activation/dropout in one block. MAISI always builds it with `conv_only=True` (e.g. `diffusion_model_unet_maisi.py:174`), so the only child is `conv: Conv3d` and it behaves exactly like a plain `nn.Conv3d`. This is the whole reason every convolution weight is named `....conv.weight` rather than `....weight`. |
| `Rearrange` | einops | Pure index shuffling, splitting/merging the attention-head axis. No parameters, no arithmetic. |
| `Identity` | PyTorch | A placeholder where monai needs the attribute to exist but no computation is wanted: `skip_connection` when input and output channels already match, and `qkv` when the three projections are *not* fused (see `SABlock`). Present so TorchScript can trace one code path. |
| `DiffusionUnetDownsample` | `diffusion_model_unet.py:272-316` | The downsampler. With `use_conv=False`, which is what MAISI uses here, it is literally `AvgPool3d(kernel_size=2, stride=2)` -- **zero parameters**. It exists only to accept the `(x, temb)` call signature that everything else in the block uses. |
| `WrappedUpsample` | `diffusion_model_unet.py:319-327` | A `monai.networks.blocks.Upsample` subclass whose `forward` throws away the `emb` argument (`del emb`). Here it is interpolation, so again no parameters. |
| `zero_module` | `diffusion_model_unet.py:51-57` | Not a layer at all -- a one-line helper that zeroes every parameter of a module and returns it. MAISI applies it to the UNet's final conv (`out.2`), which is why a *freshly built* MAISI UNet predicts exactly `0.0` until trained. The new adapters use the same helper on `proj_out`, which is where their zero-init comes from. |

### The two that carry the model's behaviour

**`DiffusionUNetResnetBlock`** (`diffusion_model_unet.py:330-442`) -- 28 of them, the UNet's workhorse:

```
out = skip_connection(x) + conv2( SiLU( norm2( conv1(SiLU(norm1(x))) + time_emb_proj(SiLU(temb)) ) ) )
```

`time_emb_proj` is a `Linear(512 -> out_channels)` and its output is broadcast over all voxels, so
**this is where every one of NVIDIA's existing conditioning signals enters the network**: timestep,
modality class label, and voxel spacing all arrive fused into that single 512-d `temb` vector, as a
per-channel additive bias. It is global by construction -- one number per channel for the whole
volume -- which is exactly why it cannot express "a lesion in the left frontal lobe" and why report
conditioning needs attention instead.

**`SpatialAttentionBlock`** (`monai/networks/blocks/spatialattention.py:20-78`) -- 11 of them, at
levels 2 and 3 and in the middle block:

```
out = x + SABlock( flatten_voxels_to_tokens( GroupNorm(x) ) )
```

Every voxel of the feature map becomes one token and attends to every other voxel. `SABlock`
(`monai/networks/blocks/selfattention.py`) is the attention math: `to_q`, `to_k`, `to_v`, `out_proj`,
all three projections separate because MAISI leaves `use_combined_linear=False` (hence the
`qkv: Identity`). **This is image-to-image attention only -- there is no text input anywhere in it.**
The new adapters are placed immediately before the blocks containing these, so the report attends at
the same resolutions where the model already reasons about spatial layout.

### The three new (non-monai) classes

| Class | What it is |
|---|---|
| `ReportCrossAttentionAdapter` | The added residual branch, laid out in section 3. Deliberately *not* monai's `SpatialTransformer`: that block bundles a second spatial self-attention plus a GEGLU feed-forward, duplicating the `SpatialAttentionBlock` right next to it at 3.55x the parameters and up to 20x the runtime. |
| `MaskedCrossAttention` | Subclasses monai's `CrossAttentionBlock`, inheriting its parameter definitions and head/scale semantics unchanged, and overrides **only** `forward` -- to accept a key-padding mask, which monai's version has no argument for (`monai/networks/blocks/crossattention.py:144`), and to route through `scaled_dot_product_attention`. Same state-dict key names as monai's block. |
| `ContextProjection` | `LayerNorm(768) -> Linear(768, 2048) -> GELU -> Linear(2048, 512) -> LayerNorm(512)`. The only module whose shape depends on the text encoder, so changing encoder changes this and nothing else. Its output is the K/V source shared by all five adapters. |
